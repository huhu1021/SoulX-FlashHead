## 路线 B 构建排错实录（10-21 续）

### 已修的四个坑（按出现顺序）
1. **NCCL 版本冲突**：requirements 锁 `nvidia-nccl-cu12==2.27.3`，torch 2.7.1+cu128 要求 `2.26.2` → ResolutionImpossible。已改为 `==2.26.2`（`requirements.txt`）。
2. **opencv-python-headless>=4.12 在容器 py3.11 无匹配版本**（`versions: none`）。且代码全项目**不直接 import cv2**，三个 cv2 变体（python/headless/contrib）共存互覆盖。已从 requirements 删除 opencv-python 和 opencv-python-headless 两行，cv2 由 mediapipe 传递依赖 opencv-contrib-python 提供。
3. **Docker Hub DNS 污染**：`registry-1.docker.io` 解析到 103.230.123.190（非 DockerHub IP）。Dockerfile FROM 改为 `docker.m.daocloud.io/pytorch/pytorch:2.7.1-cuda12.8-cudnn9-runtime`（daocloud/1ms.run/dockerproxy.net 三源实测可达，401 为未认证正常响应）。
4. **容器内 PyPI 直连 ~50KB/s**：Dockerfile 三处 pip install 均加 `-i https://mirrors.aliyun.com/pypi/simple/`（提速 10 倍+）。

### flash-attn：编译失败属预期
runtime 镜像无 nvcc（CUDA_HOME 未设），flash_attn==2.8.0.post2 源码编译必然失败 → `|| echo` 兜底生效，**服务以 SDPA 兼容模式运行**。镜像正常产出（flashhead-server:lite，15.3GB）。

### torch.compile 崩溃循环（关键坑）
现象：容器反复重启，`torch._inductor.exc.InductorError: Failed to find C compiler`。
根因：runtime 镜像无 gcc；`load_model()` 在**主线程**调 `vae.encode`，而 VAE 被 `torch.compile()` 包装（`flash_head/src/pipeline/flash_head_pipeline.py:129-139` 的 COMPILE_MODEL/COMPILE_VAE 常量），dynamo→inductor→无编译器→主进程死。
修复：给两常量加环境变量开关 `os.environ.get("FLASHHEAD_COMPILE", "1") == "1"`，compose 里设 `FLASHHEAD_COMPILE: "0"` 走 eager 模式（性能略降但句子级生成完全够用；将来要性能可在 Dockerfile 装 gcc 后把开关改回 1）。

### 教训：PowerShell 后台任务不继承工作目录
`docker compose` 系列命令在后台 PowerShell 任务里若无显式 `Set-Location`，会报 `no configuration file provided: not found` 并静默跳过 build/up（容器看似在跑实为旧容器 crash loop）。**必须显式 cd**。另外 `docker build`（default builder）与 `docker compose build`（desktop-linux builder）缓存不互通，换工具会重新下载全部 pip 依赖。
